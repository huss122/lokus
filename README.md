# Lokus

Local, privacy-first AI assistant with document search and model benchmarking. Everything runs on your own computer through Ollama: no cloud APIs, no data leaves the machine.

> **Status:** Active development

## Features

- **Local chat** – streaming answers, model picker, optional reasoning ("thinking") shown separately from the answer, stop and regenerate.
- **Conversation history** – stored in SQLite. Titles are generated by a small model (llama3.2:3b) after the answer, while the larger model handles the chat (simple model routing).
- **Base system prompt** – tells the model what it is, which model and date it runs on, and what it *cannot* do, so it says so instead of pretending. System instructions only come from the server, never from the client.
- **Document search (RAG, in progress)** – upload PDF, .txt or .md files. Text is split into sentence-aware chunks (800 characters, 150 overlap), embedded with `nomic-embed-text` and searched with cosine similarity. A test-search view shows which chunks a question retrieves, with scores.
- **Benchmark** – runs the same prompt against several models and measures time to first token, tokens per second, total time and memory/GPU use. Warm-up runs, fixed seed and temperature 0 keep runs comparable; runs that hit the token limit are flagged.

## Findings so far

Measured on a Ryzen AI 5 340 laptop (16 GB RAM, CPU only).

**Retrieval** (fictional test documents in `test_docs/`, so the model cannot answer from memory):
- 9 of 9 English single-answer questions retrieved the correct chunk first, including rephrased questions such as *"Can I work from home every day?"* → *"may work remotely up to three days per week"*.
- The similarity score cannot tell answerable from unanswerable questions: *"What is the CEO's salary?"* (not in the documents) scored 0.71, higher than several correct hits (0.65). Deciding "not in the documents" is therefore left to the language model, not a score threshold.
- Swedish questions retrieved clearly worse (scores around 0.52, 1 of 2 wrong), as the embedding model is mainly trained on English. Questions with several answers or exact numbers were also weak. Planned: multilingual embeddings and hybrid (keyword + vector) search, measured against the same questions.

**Speed:**
- qwen3.5:9b generates about 7–10 tokens/s on CPU, llama3.2:3b about 22–26 tokens/s.
- The integrated Radeon 840M (via Vulkan) was about 3.4× *slower* than the CPU for llama3.2:3b, and could not load the 9B model. A weak integrated GPU shares memory bandwidth with the CPU and gains nothing.
- With thinking enabled, qwen3.5:9b once used its whole 1,024-token budget on reasoning and returned an empty answer that looked like a valid measurement. The benchmark now stores why generation stopped and flags such runs.

## Tech stack

- **Backend:** Python, FastAPI, HTTPX, SQLite, NumPy, pypdf
- **Models:** Ollama (qwen3.5:9b, llama3.2:3b, nomic-embed-text)
- **Frontend:** HTML, CSS and vanilla JavaScript, no external libraries

## Quickstart

### Prerequisites

1. Python 3.10+
2. [Ollama](https://ollama.com/) running locally, with the models:
   ```bash
   ollama pull qwen3.5:9b
   ollama pull llama3.2:3b
   ollama pull nomic-embed-text
   ```

### Setup

1. Create a virtual environment and install the dependencies:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate          # Windows (macOS/Linux: source .venv/bin/activate)
   python -m pip install -r requirements.txt
   ```
2. Run the application:
   ```bash
   uvicorn server:app --reload
   ```
3. Open `http://127.0.0.1:8000` in your browser.

To try document search, upload the PDFs in `test_docs/` in the **Documents** tab.

## Project structure

| `rag.py` | Reading documents, chunking, embeddings and search |
| `benchmark.py` | Model benchmark runs and measurements |
| `database.py` | SQLite schema and queries |
| `static/index.html` | The whole user interface |
| `test_docs/` | Fictional documents used to test retrieval |
